## 1. 设计目标与体验支柱

从需求终稿直接推导，四条支柱，所有视觉决策都要能挂到其中一条上：

1. **扫完就能听**（S1 场景）：首次进入零学习成本，侧栏七项一眼可达，双击即播是最高频动作——播放路径上的视觉权重最高。
2. **封面是主角**（S1/F3-3）：专辑封面墙是本产品与 foobar 类工具的第一个区分点；封面图永远占据视觉 C 位，文本信息退居其下。
3. **发烧友看得见规格**（S3/F3-2）：24bit/96kHz 这类指标必须以「精确、克制、可扫读」的方式呈现——数字等宽、列对齐、徽标化，不做炫技。
4. **本地应用的确定性**（Local First）：没有加载焦虑的网络请求，UI 反馈要「即时、诚实」——操作 100ms 内有视觉确认，扫描进度真实反映，不摆假进度条。

## 2. 设计语言

### 2.1 色彩（扩展自计划 §3.7 基线，此为全集）

```css
:root {
  /* 背景阶梯（由深到浅，承载层级） */
  --bg-sidebar: #0d0d0d;      /* 侧栏：最深层 */
  --bg-base: #121212;         /* 主区 */
  --bg-elevated: #181818;     /* 卡片 / 悬浮层 / 队列面板 */
  --bg-input: #242424;        /* 输入框 / 进度槽 */
  --bg-hover: #1f1f1f;        /* 行 hover */

  /* 文本阶梯 */
  --text-primary: rgba(255,255,255,.92);   /* 标题、正文（对比度 ~15:1） */
  --text-secondary: rgba(255,255,255,.60); /* 元信息（~7:1） */
  --text-tertiary: rgba(255,255,255,.38);  /* 序号、时间戳等非正文（~3.5:1，禁止用于正文） */
  --text-disabled: rgba(255,255,255,.25);

  /* 主色：唯一强调色 */
  --accent: #1ed760;          /* 播放按钮 / 播放中高亮 / ♥ / 焦点环 / Hi-Res 徽标字 */
  --accent-hover: #1fdf64;
  --accent-active: #169c46;   /* 按压态 */
  --on-accent: #000000;       /* 主色底上的文字（播放按钮内图标） */

  /* 语义色 */
  --danger: #e22134;          /* 仅删除确认类破坏性操作 */
  --warning: #faa43a;         /* 扫描异常摘要等少见警告 */

  /* 交互面 */
  --row-hover: rgba(255,255,255,.06);
  --row-active: rgba(255,255,255,.10);   /* 选中 */
  --divider: rgba(255,255,255,.08);
}
```

用色纪律：**主色是稀缺资源**。每屏绿色元素 ≤3 处（播放按钮、播放中指示、当前焦点），其余一律灰阶；70-20-10 原则（中性 70 / 深浅灰 20 / 主色 10 以下）。收藏 ♥ 用主色绿（Spotify 心智），删除/清空才允许 --danger。

### 2.2 字体

- 栈：`"Segoe UI", "Microsoft YaHei", sans-serif`（Windows 原生，不引外部字体文件——打包体积与渲染一致性）。
- 字阶（仅 6 档，禁止自造）：`12 / 13（正文基准）/ 14 / 16（页面标题）/ 20（详情页大标题）/ 28（专辑 Hero 标题，Apple Music 式）`。字重仅 `400 / 600` 两档。
- **数字一律 `font-variant-numeric: tabular-nums`**：时长、比特率、序号、播放次数列必须等宽对齐——这是规格展示可信度的底线。
- 行高：中文语境统一 1.5；标题可用 1.3。
- Hi-Res 指标写法：`24 bit / 96 kHz`（单位小写空格分隔、中间斜杠），mp3 显示 `320 kbps`，无损显示 `FLAC`。

### 2.3 几何与间距

- 4px 基数网格；区块间距 24 / 组件间 12 / 行内 8。
- 圆角：`--radius: 6px` 全局唯一值（卡片、按钮、输入框、Toast 同值；封面图直角——唱片美学，仅播放栏迷你封面可 4px）。
- 阴影：仅悬浮层（下拉、菜单、Toast）用 `0 8px 24px rgba(0,0,0,.5)`；平面元素一律用背景阶梯区分层级，不用阴影。
- 滚动条：自定义 8px，滑块 `--text-tertiary`，hover `--text-secondary`，轨道透明。

### 2.4 图标（lucide-icons）

线性图标，线宽 2px，三档尺寸 16 / 20 / 24。核心映射（实现与设计稿统一用这套，不自造）：

| 语义 | lucide 图标 |
|---|---|
| 播放/暂停 | `play` / `pause`（播放按钮可实心填充） |
| 上一首/下一首 | `skip-back` / `skip-forward` |
| 洗牌/循环/单曲循环 | `shuffle` / `repeat` / `repeat-1` |
| 收藏 | `heart`（描边=未收藏，fill=已收藏） |
| 队列 | `list-music` |
| 音量/静音 | `volume-2` / `volume-x` |
| 搜索/设置/添加目录 | `search` / `settings` / `folder-plus` |
| 更多操作（右键替代） | `more-horizontal` |
| 文件缺失/不可播 | `file-x-2` / `ban` |
| 导航 | `music-2`(歌曲) `disc-3`(专辑) `mic-2`(艺术家) `library`(歌单) `heart`(收藏) `history`(最近播放) |

占位封面（无封面曲目/专辑）：`--bg-elevated` 底 + 居中 `music-2` 图标（`--text-tertiary`），禁止用彩色渐变占位。

### 2.5 动效

| 场景 | 规格 |
|---|---|
| hover / 按压反馈 | 150ms `cubic-bezier(0.2, 0, 0, 1)`，仅背景色/透明度变化 |
| QueuePanel 滑入滑出 | 250ms 同缓动，`translateX`，不用 opacity 渐隐 |
| 路由切换 | 主区内容 150ms fade（可选，宁缺勿滥） |
| 播放中指示 | 3 柱均衡器动画（Spotify 招牌），每柱 0.9s 错相循环，`--accent` 色 |
| 进度拖动 | 拖动中滑块放大 1.2 倍，释放回弹 |

动效红线：虚拟列表**禁止逐行进入动画**（3 万行性能）；全局响应 `prefers-reduced-motion` 时砍掉均衡器动画以外的全部动效。

## 3. 信息架构与布局系统

Shell 骨架（与计划 §3.7 一致）：

```
┌────────┬──────────────────────────────────┐
│        │  顶栏 56px：页面标题 + SearchBox   │
│ 侧栏    ├──────────────────────────────────┤
│ 232px  │                                  │
│        │        主内容区（独立滚动）         │
│ 导航7项 │                                  │
│ ────── │                                  │
│ 歌单列表│                                  │
├────────┴──────────────────────────────────┤
│  PlayerBar 72px（常驻）        [Queue 320px 滑入覆盖主区右侧] │
└───────────────────────────────────────────┘
```

- 侧栏结构：上区固定导航 7 项（歌曲/专辑/艺术家/歌单/收藏/最近播放/设置，F3-1 顺序），下区「我的歌单」列表（可滚动），两区之间 1px `--divider`。当前页导航项：`--text-primary` + 左侧 3px `--accent` 指示条（无底色高亮——遵守用户 UI 偏好：无底色、前置指示）。
- 窗口：默认 1280×800，min 960×640；**窄窗降级**：主区 <1100px 隐藏 Songs 的比特率列，<1000px 再隐藏采样率·位深列（时长与格式永不隐藏）。侧栏固定宽不折叠（0.1 不做）。
- 落地页 = Songs（F3-1）。空库时 Songs 页显示引导空态直达设置页。

## 4. 逐页面设计规格

> 通用约定先行：所有列表/网格页必须覆盖 **页面态矩阵**（空库 / 扫描中 / 正常 / 搜索无结果）与 **行级态矩阵**（normal / hover / playing / missing / 不可播 / selected）。下文只写各页特有差异，重复态不再赘述。行高 48px，封面列 40px 图，hover 时行首浮现播放键（替代序号——Spotify 招牌交互，采用）。

### 4.1 Songs（歌曲，落地页）｜F3-2

- 列：封面 44 / 序号 40 / 标题 minmax(200,2fr) / 艺术家 1fr / 专辑 1fr / 时长 64 / 格式 56 / 比特率 72 / 采样率·位深 110（px）。表头 32px，`--text-secondary` 12px 大写风格不适用中文——用 12px + `--text-secondary` 即可，点击排序的列头带 ▲▼ 指示（`chevron-up/down` 12px）。
- 播放中行：标题与均衡器用 `--accent`，行背景不变（克制）；missing 行整体 `--text-tertiary` + 尾部 `file-x-2` 小图标（**中性灰，不是红色错误**）；不可播行播放图标禁用态，hover 提示「此格式 M0.1 暂不支持播放，0.5 版恢复」。
- 右键菜单：下一首播放 / 添加到队列 / 收藏或取消 / 添加到歌单 ▸（子菜单=歌单列表+新建）。菜单 `--bg-elevated`，item hover `--row-hover`。
- 参考：Spotify 歌曲列表的行密度与 hover 播放键；避其双击/单击语义混淆——本项目**单击选中、双击播放**（桌面传统，符合 S4 高频操作）。

### 4.2 Albums（专辑网格）｜F3-3

- 网格 `auto-fill minmax(160px, 1fr)`，卡片 = 封面（256 档）+ 标题一行截断 + 艺术家 `--text-secondary`。
- 卡片 hover：右上角浮现 40px 绿色圆形播放按钮（`--on-accent` 图标），封面轻微提亮（`filter: brightness(1.1)`）。
- 参考：Spotify 专辑墙；避其圆角卡片阴影层——本项目卡片无底色，纯封面+文字（更冷静，突出封面本身）。

### 4.3 AlbumDetail（专辑详情）｜F3-5

- Hero 区（Apple Music 式排版）：左封面 200px 直角；右侧 28px 大标题 + 艺术家 `--text-secondary` + 元信息行「年份 · 曲目数 · 总时长」。Hero 背景：封面主色提取的**低饱和深色渐变**（自封面色向 `--bg-base` 过渡，高度 280px）——0.1 获准的两处渐变之一（另一处为 §4.6 Liked Hero 的 `--accent` 12% 渐变；除此两处全应用不使用渐变）。
- 操作行：播放（实心绿圆 48px）/ 随机播放（描边圆 48px，`shuffle` 图标）。
- 曲目表：Disc 编号分组行（有 disc>1 时），列=序号/标题/艺术家/时长；当前播放行同 §4.1 高亮。
- 参考：Apple Music 详情页的排版层级；避其 iOS 圆角大卡与毛玻璃。

### 4.4 Artists / ArtistDetail（艺术家）｜F3-4 / F3-6

- Artists：列表行 = 44px 圆形占位头像（`mic-2` 图标）+ 名称 + 右侧曲目数 `--text-tertiary`。0.1 无真实头像（0.5 联网补），占位必须统一克制。
- ArtistDetail：Hero 同专辑式（头像区用大号占位圆），下方「专辑」网格 + 「全部曲目」表两段式。基础版不含 bio/热门曲目（0.5）。
- 参考：Spotify 艺术家页的灰阶克制；避其大图轮播。

### 4.5 Playlists / PlaylistDetail（歌单）｜F6-3

- Playlists：卡片式（同专辑网格尺寸），封面 = CollageCover 2×2 拼贴（不足 4 首用占位色块补位，色块取 `--bg-input`）；卡片右下角浮层歌单名？不——歌单名放封面下方，与专辑卡一致。
- 新建：网格首位「新建歌单」虚线框卡（`plus` 图标 + 「新建歌单」文案）→ 点击行内命名（输入框内联，Enter 确认 Esc 取消，禁止弹窗）。
- PlaylistDetail：Hero 同专辑详情（拼贴封面），操作行多「重命名」（双击标题内联编辑，同新建交互）；曲目表支持 **拖拽重排**：拖起行 60% 透明度，目标行上缘 2px `--accent` 插入线，释放即时生效（F6-3 验收核心）。
- 参考：Spotify 歌单详情；其「时间线头部歌曲行」0.1 不做（范围外）。

### 4.6 Liked（收藏）｜F6-1

- Hero：绿色渐变底（`--accent` 12% 透明度向 `--bg-base`）+ 大标题「收藏」+ 曲目数；排序切换用下拉（`arrow-up-down` 图标 + 当前排序名），白名单 5 键（favorited_at/artist/album/title/playCount）。曲目表 = TrackList 复用。
- 参考：Spotify Liked Songs 紫色 Hero → 本项目改用主色绿的**低透明度**渐变，同构不同色。

### 4.7 Recent（最近播放）｜F7-2

- 简单列表页：时间列放最右（相对时间文案：「3 分钟前 / 昨天 / 3 天前」，>7 天显示日期），其余同 TrackList。无 Hero、无排序（按时间倒序锁死）。

### 4.8 Settings（设置）｜F8-1/F8-2

- 左侧分区锚点导航（General / Library / Playback / About，激活项同侧栏样式），右侧表单区 max-width 640px。
- 控件规范：开关 = 40×22 圆角滑块（开=`--accent`）；目录列表行 = 路径（等宽省略中段：`D:\...\Music`）+ 启用开关 + 删除图标（点击弹内联确认条，不用系统对话框）；「全量重扫」按钮旁实时进度条（`--bg-input` 槽 + `--accent` 填充 + 「1,234 / 30,000 · 解析中」文案）——扫描进度是这个页面的灵魂，必须真实、可中断观感（0.1 不可中断，文案不给「取消」按钮即诚实）。
- Playback 分区：仅音量默认值说明 + 「实际音量请在播放栏调节」文案；Metadata/Cache 不渲染（0.5），About 区声明规划中。
- About：版本号（等宽）+ 已知限制八条（终稿 §8，逐条原文）+ 致谢列表（Electron/Chromium/SQLite/music-metadata/sharp/React）。

### 4.9 SearchResults + SearchBox（搜索）｜F3-7

- SearchBox：顶栏 320px，`--bg-input` 圆角胶囊，左 `search` 图标；focus 时宽度 400px 过渡（250ms）+ 2px `--accent` 描边。
- 下拉预览（输入 debounce 200ms）：`--bg-elevated` 面板，四组各前 5 条，组头「歌曲/专辑/艺术家/歌单」+ 右侧「查看全部」；无结果组直接不渲染该组。
- 全结果页：四段式分区（TrackList / 专辑网格 / 艺术家列表 / 歌单卡），每段组头 16px 标题 + 计数。
- 空结果态：居中「没有找到与 “{q}” 匹配的内容」+ 换个关键词建议文案。

### 4.10 PlayerBar（播放栏）｜F4-3

三段式：左（64px 封面 + 标题/艺术家双行，标题可点击跳专辑详情）｜中（控制键排 + 进度条 40% 宽）｜右（队列、音量 120px）。控制键从左到右：shuffle / previous / **播放暂停（32px 白色圆形按钮，`--bg-base` 底黑图标——唯一反色元素，全场视觉锚点）** / next / repeat / heart。
- 进度条与音量条：4px 槽，`--bg-input` 底 + `--text-secondary` 已播填充（**已播不用主色绿**——绿色留给播放按钮，避免双绿竞争；Spotify 实测绿槽过艳，此处取其形调其色），hover 槽增高至 6px + 浮现拖点。
- 时间显示 `1:23 / 4:56` 等宽 12px `--text-tertiary`。
- 当前曲目即播放中：左侧封面带 3 柱均衡器角标。

### 4.11 QueuePanel（队列面板）｜F5-3

- 320px 覆盖主区右侧，`--bg-elevated`，左缘 1px `--divider` + 8px 阴影；头行「播放队列」+ 清空？——0.1 无清空（范围外），只有标题与关闭键。
- 「正在播放」区块 + 「下一首播放」区块（插队曲，视觉上与主队列间用 1px divider 分隔）+ 「下次播放」主队列（只读；拖拽重排/删除属 F5-4 禁区，不渲染任何编辑 affordance）。
- 当前曲行 = `--accent` 标题 + 均衡器；插队曲行首带 `corner-down-right` 小图标。

## 5. 参考产品研究（学什么 / 避什么）

| 产品 | 学 | 避 |
|---|---|---|
| **Spotify**（骨架基准） | 深 12 号灰阶体系、hover 浮现播放键、播放行均衡器、 Liked 渐变 Hero、行密度 | 大圆角卡片阴影层、绿色进度槽过艳、歌单侧栏无限堆叠 |
| **Apple Music**（排版基准） | 详情页 Hero 排版（28px 大标题 + 元信息行）、字阶纪律、封面直角 | iOS 化手势、毛玻璃/ vibrancy（Electron 合成成本 + 禁忌清单） |
| **网易云音乐**（华语语境） | 文案口吻（「收藏」「添加到歌单」）、搜索分组心智 | 红色主题、动态皮肤、信息流首页（0.1 无 Home 页） |
| **MusicBee / foobar2000**（规格呈现） | 规格列精确对齐、Hi-Res 指标可信度 | 工程师审美：密集工具栏、可换肤复杂度、默认字小 |

设计倾向一句话：**Spotify 的骨架 + Apple 的排版纪律 + 工具级的规格诚实**，三者冲突时取克制。

## 6. 状态与反馈设计

| 组件 | 规格 |
|---|---|
| 空库态（Songs 首见） | 居中：`folder-plus` 48px `--text-tertiary` + 「添加你的第一个音乐目录」16px + 说明一行 13px secondary + 绿色实心按钮「前往设置」。**线性图标 + 文案 + 单一动作**，禁止插画 |
| 扫描中 | 设置页进度条（§4.8）+ 侧栏「歌曲」项右侧实时计数徽标（`--text-tertiary` 12px）；列表页无需骨架屏——SQLite 查询毫秒级，首帧即全量数据 |
| Toast | 右下角（播放栏上方 16px），`--bg-elevated` + 8px 阴影，3s 自动退场，队列「已添加到队列」「已收藏」、格式不支持提示共用；同型 Toast 3s 内去重 |
| 骨架屏 | 不做（本地数据无网络延迟，摆假加载违反「诚实」支柱） |
| 危险确认 | 删除歌单/移除目录：行内确认条（红字「确认删除？」+ 确认/取消），3s 无操作自动收回；不用系统弹窗 |
| 焦点环 | 键盘导航时 2px `--accent` outline offset 2px；鼠标点击不显示（`:focus-visible`） |

## 7. 可达性与品质底线

- 文本对比度：正文级 ≥4.5:1（primary/secondary 达标）；`--text-tertiary` 仅限序号/时间戳等辅助信息。
- 点击目标 ≥28×28px（行内图标按钮）；列表行整行可点选中。
- Tab 顺序固定：侧栏 → 主区 → 播放栏；全键盘可达是硬要求（无键盘死区）。
- 中文排版：标点悬挂不强制，但列表截断一律 `text-overflow: ellipsis` 单行 + `title` 提示全文；禁止两行截断（`-webkit-line-clamp` 不用于列表）。
- 300% 缩放不破版（Windows 缩放 125%/150% 是常态，测试必过——高 DPI 是 Windows 桌面应用第一翻车点）。

## 8. 禁忌清单（Anti-patterns，逐条硬禁）

1. 不做浅色主题、不做主题切换入口（0.1 锁深色单主题）。
2. 不引入 Tailwind / 任何 UI 组件库 / CSS-in-JS——**自写 CSS 变量 + 纯 CSS**（与计划 §3.1 锁定一致；Frontend Design 技能默认推荐 Tailwind，本项目显式豁免该条）。
3. 不做玻璃拟态、大面积 backdrop-blur、渐变文字、霓虹发光、霓虹描边。
4. 不用 emoji 当图标；不用插画式空态；不用彩色渐变占位封面。
5. 列表行不放大图（封面列上限 40px 显示尺寸）；网格封面只有 256 一档。
6. missing 状态禁止红色/警告色（它是「文件暂时不在」的中性事实）。
7. 不做侧栏折叠、可换肤、可配置密度（全部 YAGNI）。
8. 虚拟列表禁逐行动画；全局动效时长 ≤250ms。
9. 禁止系统原生弹窗（确认/输入一律内联）——桌面壳里的网页弹窗是最廉价信号。
10. 不新增页面、组件、交互超出 §4 清单；发现「需要加个 XX 才完整」时停下回报，不自行扩权。
11. UX 文案：中文，按钮用动词短语（「添加目录」非「目录」），空态必给下一步动作；禁止「哎呀，出了点问题」式卖萌与「操作成功」式废话（成功的操作用行为反馈，不打断）。
12. 主色克制律（§2.1）：任何一屏绿色元素 >3 处即为设计缺陷，回改。
